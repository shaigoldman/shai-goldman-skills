# Mobile conversion

- Choose intentionally: a PWA installs from a browser but is not automatically a store package; a remote-site WebView wrapper requires network and inherits server changes; a bundled hybrid app can run offline if all assets and APIs are local; native implementations offer deeper platform integration but require additional work. A store release has signing, policy and account requirements. Do not equate a debug APK with a published app.
- Reuse a working browser implementation where it meets requirements. Verify that Android WebView / iOS WebKit supports the particular WebAssembly, module worker, fetch and parallel APIs actually used. Handle low memory, interruption, keyboard and safe-area insets, back/navigation, accessibility, external links, network failure, app lifecycle and platform versions. Test on target devices or emulators; performance results from desktop or a simulation do not establish phone behavior.
- For a WebView, restrict navigation, avoid JavaScript bridges unless necessary, avoid broad file access, and open external links appropriately. For bundled Android content prefer a secure web-like local origin, avoiding file URL cross-origin pitfalls. Confirm MIME types, worker loading and local fetch work on the platform. Use maintained supported toolchains and current platform documentation.
- Provide installable debug artifacts for testing without treating their temporary signing key as a release identity. Store release keys securely; never commit secrets. Play/App Store publication, developer identity, privacy disclosures and distribution channels require their respective setup. Do not claim release until verified.
