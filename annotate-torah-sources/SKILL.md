# Annotate Torah sources

Treat the author's argument as an interpretive project, not a collection of search keywords. Preserve their learning, style and original manuscript. Carry authorized work through all entries, checking each occurrence in order. Never present a partial index as exhaustive.

1. Identify the current manuscript, full notes, requested deliverable and preferred source-location convention. Read current user-provided files; prior conversation is not their current contents. Use supplied file snapshots directly. Preserve Library identity for authorized edits and save new deliverables according to environment rules.
2. Extract text and locations with `scripts/pdf_inventory.py` for PDF and `scripts/docx_footnotes.py` for Word. For Pages, seek reliable conversion; if unable, use extractable text and clearly label unreliable pagination. Never invent page, paragraph, amud or halacha. For RTL multi-column pages, visually verify physical order and paragraph boundaries; count continuation paragraphs and headings consistently. User's convention wins.
3. Make a source ledger listing every citation occurrence, including repeats, implicit claims, existing and empty footnotes. Track source and summary locations, original paragraph opening, exact original reference, whether direct quotation is present in notes, evidence and uncertainty. Scan footnote markers and compare against footnote content; report unverified missing numbers and exceptions. Automatic matching generates candidates only, never conclusions.
4. Compare: user's claim, complete surrounding discussion in full notes, and original text independently. Distinguish actual source language, summaries in user notes, and proposed interpretation. Locate the exact relevant dibbur, amud, siman/se'if katan, chapter/halacha and edition; verify online authoritative originals when needed. A similar passage found elsewhere is additional support, not the source quoted in the notes. Check whether text proves the particular proposition; flag tensions, qualifications and apparent contradictions.
5. Quote accurately from supplied or lawfully accessible sources within applicable quotation limits; give precise citations, quote only exact language, clearly mark every omission with ellipses and distinguish paraphrases. Check variants and halacha-number differences between editions. Use longer text provided by the user when needed. A secondary work reproducing an original is a witness, not direct inspection of the original edition; say so. Where source cannot be established, mark explicitly; never manufacture wording or references.
6. If requested, prepare a sequential source index and appendix containing complete relevant passages from the user's full notes and separately identified primary-source excerpts. For note suggestions, write copy-ready Hebrew and give exact locations. Maintain distinct, independently numbered occurrences and repeat references where appropriate. Correct mistakes transparently. If substantive edits were not requested, propose them rather than silently changing the author's argument.
7. For DOCX/PDF deliverables use the environment's document/PDF workflows and inspect the latest rendered output, including every page where note layout, RTL alignment, numbering or line breaks change. Use true linked notes where appropriate. Verify references, numbering, unmatched entries and actual note content. Right alignment and RTL writing direction are separate; render before delivery and check both. Do not claim validation not performed.

Consult [references/research.md](references/research.md) when reconciling textual or conceptual differences; [references/workflow.md](references/workflow.md) for extraction, ledger, and document QA; and [references/regressions.md](references/regressions.md) for failure patterns. Run scripts with `--help`; they print machine-readable JSON and never modify original inputs.
